# 命令行工具

`json2pptx` 提供 10 个子命令：`unpack`（解包）、`repack`（重建）、`view`（视图）、`edit`（修改）、`render`（渲染）、`query`（选择器查询）、`validate`（结构校验）、`dump`（导出可回放指令）、`schema`（Schema 指引）、`templates`（模板列表）。CLI 采用**无状态**设计：命令之间不共享任何隐藏配置或缓存，输入输出均由参数显式指定——`view` / `edit` / `render` / `query` / `validate` / `dump` 可直接操作 unpack 产物目录，或对 PPTX 一次性解包到临时目录（结束后自动删除）。

---

## 概览

| 命令 | 功能 |
|------|------|
| `unpack <输入.pptx> -o <目录>` | PPTX → 可编辑中间产物（按幻灯片拆分的 JSON + 媒体目录） |
| `repack <产物目录> -o <输出.pptx>` | 中间产物 → PPTX |
| `view <输入> /slide[N] text\|layout` | 第一层视图：文本+媒体 / 组件布局（树形） |
| `edit <输入> <路径> <get\|set\|add\|remove> [-o <输出.pptx>]` | 第二层精准修改 |
| `render <输入> /slide[N] [-o <png>]` | 将幻灯片渲染为 PNG（browser / native 引擎） |
| `query <输入> <选择器>` | 类 CSS 选择器筛选元素 |
| `validate <输入>` | 结构校验（越界/空文本/缺图/表格列数…） |
| `dump <输入>` | 导出可回放编辑指令 JSON |
| `schema` | 打印 JSON Schema 文档指引 |
| `templates` | 列出全部 6 种模板预设 |

> `view` / `edit` / `render` / `query` / `validate` / `dump` 的 `<输入>` 可以是 PPTX 文件（一次性解包到临时目录，命令结束后自动删除）或 unpack 产物目录（直接读写用户文件）。

## 运行方式

### 方式一：cargo 直接运行（无需安装）

```bash
cargo run --release --bin json2pptx -- unpack input.pptx -o out/
```

### 方式二：全局安装

```bash
# 在仓库根目录执行（workspace 包含 cli 成员）
cargo install --path cli

# 安装后直接调用（二进制名为 json2pptx）
json2pptx unpack input.pptx -o out/
```

> 下文示例统一使用 `json2pptx`；使用方式一运行时把前缀替换为 `cargo run --release --bin json2pptx --` 即可。若想使用更短的命令名，可自行创建符号链接或 shell 别名。

## 1. unpack — PPTX 解包为可编辑中间产物

将 PPTX 解包为**按幻灯片拆分的 JSON + 媒体目录**（包镜像结构），方便逐页编辑后重建：

```
out/                            # json2pptx unpack in.pptx -o out/
├── presentation.json           # 顶层结构（meta/theme/尺寸），slides 为文件路径数组
└── ppt/
    ├── slides/
    │   ├── slide1.json         # 每张幻灯片一个 JSON（背景/过渡/元素）
    │   └── slide2.json
    └── media/
        ├── image1.png          # 媒体文件实体（保留包内路径）
        └── image2.jpg
```

```bash
json2pptx unpack <input.pptx> [-o <目录>]
```

| 参数 | 说明 |
|------|------|
| `input` | 输入的 PPTX 文件路径（必填） |
| `-o, --output` | 输出的目录路径；缺省为输入文件名去掉扩展名（`demo.pptx` → `demo/`） |

**产物约定**：

- `presentation.json` 的 `slides` 字段为**文件路径数组**：`["ppt/slides/slide1.json", ...]`
- 每个 `slideN.json` 是标准 `Slide` 结构（与 `parse` 输出的单页一致），可直接编辑
- 图片 `src` 统一为包内路径 `ppt/media/imageN.ext`（相对产物根）；编辑时改为 URL 也会被保留

### 示例

```bash
# 解包到 demo/ 目录
json2pptx unpack demo.pptx -o demo/

# 编辑 demo/ppt/slides/slide1.json 后重建
json2pptx repack demo/ -o demo_new.pptx
```

## 2. repack — 从中间产物重建 PPTX

`repack` 是 `unpack` 的逆操作：读取产物目录中的 `presentation.json` 与各 `ppt/slides/slideN.json`，将图片 `src` 解析为产物目录内的实际路径，重新生成 PPTX。

```bash
json2pptx repack <目录> [-o <output.pptx>]
```

| 参数 | 说明 |
|------|------|
| `input` | 输入的 unpack 产物目录（含 `presentation.json`） |
| `-o, --output` | 输出的 PPTX 路径；缺省为目录名加 `.pptx`（`demo/` → `demo.pptx`） |

> 典型工作流：`unpack` → 编辑各 `slideN.json`（或替换 `ppt/media/` 下的图片）→ `repack` 重建，全程保留媒体路径。

## 3. view — 第一层视图

对单个幻灯片输出只读结构化信息（JSON）。输入可以是 PPTX 文件或 unpack 产物目录：

- **PPTX 文件**：一次性解包到临时目录，命令结束后自动删除，不产生任何残留；
- **unpack 产物目录**：直接读取，媒体 `src` 统一为产物中媒体文件的**绝对路径**（URL 保留）。

```bash
json2pptx view <输入> /slide[N] text|layout
```

### view text — 文本 + 媒体（去样式/图形，树形）

```json
{
  "slide": 1,
  "texts": [
    { "name": "TextBox 2", "text": "标题文本" },
    { "name": "Group 4", "children": [
        { "name": "TextBox 5", "text": "组内文本" }
    ]}
  ],
  "media": [
    { "name": "Picture 3", "src": "/abs/.../ppt/media/image1.png" },
    { "name": "background", "src": "https://example.com/bg.png" }
  ]
}
```

- `texts`：文本元素 + 表格单元格文本，group 递归；**不含样式/图形信息**
- `media`：图片元素 + 背景图；**绝对路径**或 URL

### view layout — 组件布局（树形，只保留组件名/文字/位置）

```json
{
  "slide": 1,
  "layout": [
    { "type": "group", "name": "组一", "position": { "x": 4, "y": 3, "w": 5, "h": 3 },
      "children": [
        { "type": "text",  "name": "TextBox 5", "text": "组内文本", "position": { ... } },
        { "type": "shape", "name": "Shape 6",   "position": { ... } }
      ]},
    { "type": "text", "name": "TextBox 2", "text": "标题文本", "position": { ... } }
  ]
}
```

覆盖全部 22 种元素类型（基础 text/shape/line/image/table/group/icon/formula/chart/comment/equation/opaque + 10 种组件），组件保留核心字段（value/data 等）；`line_chart` / `pie_chart` / `ring_chart` 额外显示 `labels`。

### view text — 备注输出

`view text` 顶层额外输出 `notes`（该页演讲者备注，无备注时为 `null`）：

```json
{
  "slide": 1,
  "texts": [ ... ],
  "media": [ ... ],
  "notes": "第一页要点\n第二行"
}
```

## 4. 路径语法与元素

`view` 与 `edit` 共用同一种树形路径来定位幻灯片与元素。路径以 `/` 开头，由若干段组成，每段格式为 `类型[索引]`，索引**从 1 开始**。

```text
/slide[N]                            # 幻灯片
/slide[N]/type[M]                    # 第 M 个某类型元素
/slide[N]/type[@name=Title]          # 按元素名称定位（选择窗格名称）
/slide[N]/group[K]/type[M]           # 分组内嵌套元素（递归下钻）
/slide[N]/type                         # 省略索引 = 该类型第 1 个
```

### 语法规则

| 规则 | 说明 |
|------|------|
| 以 `/` 开头 | 否则报错 `路径必须以 / 开头` |
| 第一段必须是 `slide` | 否则报错 `路径第一段必须是 slide，实际: X` |
| 每段格式 `类型[索引]` | 缺少 `[` 报 `路径段缺少索引`；`]` 非末位报 `路径段格式错误` |
| 索引、从 1 开始 | `type[0]`、`type[x]`、`type[1]junk` 均被拒绝；`type[0]` 报 `索引从 1 开始`；`type` 省略索引时默认第 1 个 |
| `[@name=X]` 选择器 | 按元素名称定位：`/slide[1]/shape[@name=Logo]`；`[@id=N]` 暂不支持 |
| 索引按类型单独计数 | 索引是该类型在当前容器内的第 N 个，无关类型不参与计数 |
| 中间节点必须是 `group` | 非 group 元素无子级，继续下钻报 `路径中间节点 X 不是分组，无法继续下钻` |
| 越界报错 | 幻灯片越界 `幻灯片索引越界: /slide[N]（共 M 张）`；元素未命中 `未找到第 N 个 X 元素（该类型共 M 个）` |

### 可用元素类型（22 种）

| 类型 | 说明 |
|------|------|
| `text` | 文本 |
| `shape` | 形状 |
| `line` | 线条 |
| `image` | 图片（可含视频/音频 `media`） |
| `icon` | 图标 |
| `formula` | LaTeX 公式 |
| `table` | 表格 |
| `chart` | 真实图表（解析自 `ppt/charts/*.xml`） |
| `comment` | 批注 |
| `equation` | Office 公式（原始 OMML） |
| `opaque` | 不透明富对象（OLE/SmartArt/3D/zoom） |
| `group` | 分组（唯一可作为中间下钻节点的类型） |
| `progress_bar` | 进度条 |
| `progress_ring` | 进度环 |
| `bar_chart` | 柱状图 |
| `line_chart` | 折线图 |
| `pie_chart` | 饼图 |
| `ring_chart` | 环形图 |
| `kpi_card` | KPI 卡片 |
| `rating_stars` | 星级评分 |
| `timeline` | 时间轴 |
| `process_flow` | 流程 |

> 元素类型名与 JSON 的 `type` 字段一致，由 `Element::type_name()` 提供，是路径寻址的权威来源。

### 示例

```text
/slide[1]                        # 第一张幻灯片
/slide[2]/text[3]                # 第二页第 3 个文本
/slide[1]/group[1]/image[2]      # 第一页第 1 个分组内的第 2 张图片
/slide[1]/lineChart[1]           # 高级组件（折线图）
```

### 注意事项

- **寻址范围**：`view` 与 `edit` 的 `get` / `set` / `remove` 可寻址上述全部 22 种；但 `edit add --type` 只能新建其中 10 种：`text` / `shape` / `line` / `image` / `table` / `group` / `line_chart` / `pie_chart` / `ring_chart` / `progress_bar`。
- **组件 round-trip 限制**：`progress_bar`、`line_chart` 等高级组件在 `repack` / 解析回环后会展开为 `Group` 形状，回环后若仍按原组件类型寻址会失败。

## 5. edit — 第二层精准修改

修改幻灯片。根据输入类型有两种语义：

- **unpack 产物目录**：原地修改产物中的 `slideN.json`，之后用 `repack` 重建 PPTX；
- **PPTX 文件**：写入操作（set / add / remove）必须指定 `-o <输出.pptx>`，一次性完成 unpack → 修改 → repack，**不原地改写输入文件**（无状态）；只读操作 `get` 无需 `-o`。

```bash
json2pptx edit <输入> <路径> <get|set|add|remove> [--prop k=v]... [--type T] [-o <输出.pptx>]
```

> 路径语法与可用元素类型见上方「4. 路径语法与元素」。`view` 与 `edit` 共用同一路径。

### 操作

| 操作 | 示例 | 说明 |
|------|------|------|
| `get` | `edit in.pptx /slide[1]/text[1] get` | 输出节点精简结构（type/name/text/position） |
| `set` | `edit in.pptx /slide[1] set --prop background=#1a1a2e -o out.pptx` | 幻灯片级：background（纯色/渐变/图片）、transition、notes |
| `set` | `edit in.pptx /slide[1]/text[2] set --prop text=新文本 --prop font_size=40 -o out.pptx` | 元素级：text/name/x/y/w/h/font_size/bold/color/align/rotation/fill/shape_type/src |
| `set` | `edit in.pptx /slide[1]/line[1] set --prop color=E74C3C --prop dash=dashed -o out.pptx` | line：points/color/width/dash/arrow_start/arrow_end/smooth |
| `set` | `edit in.pptx /slide[1]/lineChart[1] set --prop data=10,20,15 --prop labels=Q1,Q2,Q3 -o out.pptx` | 图表组件：data/labels/colors/max/thickness/show_values/axis |
| `add` | `edit in.pptx /slide[1] add --type text --prop text=段落 --prop x=1 --prop y=7 --prop w=6 --prop h=1 -o out.pptx` | 在 slide 或 group 下新增元素 |
| `remove` | `edit in.pptx /slide[1]/group[1]/shape[1] remove -o out.pptx` | 删除路径指向的元素 |

`add` 的 `--type` 支持：`text` / `shape` / `line` / `image` / `table` / `group` / `line_chart` / `pie_chart` / `ring_chart` / `progress_bar`。

- `line`：`points="x1,y1,x2,y2"`（成对）、`color`、`width`、`dash`、`arrow_start`、`arrow_end`、`smooth`
- 图表组件：`data="10,20,30"`（逗号分隔）、`labels="Q1,Q2,Q3"`、`colors="FF0000,00FF00"` 等

> **能力边界**：run 级 `hyperlink`（文本内 run 结构）与单元格级 `colspan`/`rowspan`/`column_widths`（表格深层结构）不通过 CLI set 直接修改——可编辑 unpack 产物的 `slideN.json` 后 `repack`，`view` / `get` 均可查看。

### 典型工作流

```bash
# 查看第 1 页的文本与媒体（.pptx 一次性解包，无残留）
json2pptx view deck.pptx /slide[1] text

# 一次性修改并输出新文件（原文件不变）
json2pptx edit deck.pptx /slide[1]/text[1] set --prop text=新标题 -o new.pptx

# 多次修改：先解包到产物目录，逐条原地修改，最后重建
json2pptx unpack deck.pptx -o deck_product/
json2pptx edit deck_product/ /slide[1]/text[1] set --prop text=新标题
json2pptx edit deck_product/ /slide[1] add --type text --prop text=正文 --prop x=1 --prop y=2 --prop w=8 --prop h=2
json2pptx repack deck_product/ -o new.pptx
```

## 6. render — 渲染幻灯片为 PNG

```bash
json2pptx render <输入> /slide[N] [-o <输出.png>] [--engine browser|native] [--scale N]
```

| 参数 | 说明 |
|------|------|
| `input` | PPTX 文件或 unpack 产物目录（同 `view`） |
| `-o, --output` | 输出 PNG 路径；缺省为 `<输入名>_slide[N].png` |
| `--engine` | `browser`（默认，复用 web 前端渲染，需已构建 `web/dist` 且装有 Chrome/Edge）或 `native`（Rust resvg 矢量近似，不依赖浏览器） |
| `--scale` | 渲染缩放倍率（browser 引擎 = 图像像素倍率，`1` = 96dpi） |

输入为 PPTX 时同样一次性解包到临时目录，渲染完成后自动清理。

## 7. query — 类 CSS 选择器查询

```bash
json2pptx query <输入> "<选择器>"
```

输出 `{ "matches": [ { "path", "type", "name", "text"?, "position" } ], "count": N }`。

| 选择器片段 | 说明 |
|-----------|------|
| `slide[N]` | 限定第 N 张幻灯片（须在最前） |
| `类型名` | `text` / `shape` / `image` / `table` / `chart` / `group` …；`*` 为通配 |
| `[name=X]` | 按元素名称 |
| `[text=X]` / `text:contains("X")` | 文本包含 |
| `:empty` | 文本为空 |

```bash
json2pptx query deck.pptx 'text'
json2pptx query deck.pptx 'slide[1] shape[name=Title]'
json2pptx query deck.pptx 'text:contains("Hello")'
```

## 8. validate — 结构校验

```bash
json2pptx validate <输入>
```

输出 `{ "issues": [ { "path", "severity", "message" } ], "count": N }`。
检查项：元素越界、宽/高为 0、文本为空、图片缺 `src`、表格各行物理列数不一致、图表无数据系列、同一页名称重复。

---

## 9. dump — 导出可回放编辑指令

```bash
json2pptx dump <输入>
```

输出 `{ "version": 1, "size": {...}, "commands": [ … ] }`：每张幻灯片一条 `set`（background/transition/notes），每个元素一条 `add`（`type` + 完整 `props` JSON）。

## 常见组合用法

| 场景 | 命令 |
|------|------|
| 拿到他人 PPTX，逐页查看内容 | `view in.pptx /slide[1] text` / `layout`（.pptx 一次性解包，无残留） |
| 一次性修改并输出新文件 | `edit in.pptx /slide[1]/text[1] set --prop text=新标题 -o new.pptx`（原文件不变） |
| 多次修改同一份 PPT | `unpack in.pptx -o out/` → 多次 `edit out/ ...`（原地修改）→ `repack out/ -o new.pptx` |
| 深度编辑（含媒体替换） | `unpack in.pptx -o out/` → 编辑 `out/ppt/slides/*.json` 与 `out/ppt/media/*` → `repack out/ -o new.pptx` |
| 验证回环一致性 | `unpack a.pptx -o out/ && repack out/ -o b.pptx`，比较两文件内容 |
| 按名/内容查找元素 | `query in.pptx 'slide[1] shape[name=Logo]'` / `query in.pptx 'text:contains("快照")'` |
| 检查排版问题 | `validate in.pptx`（越界/空文本/缺图/表格列数等） |
| 导出可回放指令 | `dump in.pptx > spec.json` |
| 了解 JSON 结构 | `view in.pptx /slide[1] layout` + [JSON格式规范](JSON格式规范.md) |
