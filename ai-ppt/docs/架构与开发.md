# 架构与开发

本文档面向希望深入了解 `json2pptx` 内部实现或参与开发的读者，介绍架构设计、模块职责、生成/解析管线、关键技术点与测试体系。

---

## 1. 架构总览

```
┌──────────────┐      ┌───────────────┐      ┌─────────────┐
│  JSON 描述    │ ──▶  │  OOXML 部件   │ ──▶  │  PPTX 文件  │
│  (serde)     │ gen  │  (String)     │ zip  │  (.zip)     │
└──────────────┘      └───────────────┘      └─────────────┘
       ▲                                             │
       └────────────────── parse ────────────────────┘
```

- **生成方向**：JSON → Rust 模型（serde）→ OOXML XML 字符串（quick-xml）→ ZIP 打包（zip crate）→ `.pptx`
- **解析方向**：`.pptx` → ZIP 解压 → XML 流式解析（quick-xml Reader）→ Rust 模型 → JSON

核心设计原则：

1. **零 Office 依赖**：OOXML 全部手工生成与解析，不依赖任何 MS Office / PPTX SDK；
2. **单一母版 + 单一版式**：生成最小化的 slideMaster/slideLayout，所有元素在 slide 级别绝对定位；
3. **双向回环**：生成与解析共享同一套数据模型，保证 JSON → PPTX → JSON 的一致性；
4. **AI 友好**：JSON 模型简洁（无 OOXML 噪音），适合 LLM 直接生成与编辑。

## 2. 依赖选择

| 用途 | Crate | 理由 |
|------|-------|------|
| ZIP 读写 | `zip` 2.x | 最成熟的 Rust zip 库 |
| XML 生成 | `quick-xml` 0.36+ Writer | 高性能流式写入 |
| XML 解析 | `quick-xml` Reader | 流式解析，低内存 |
| JSON | `serde` + `serde_json` | Rust 标准序列化方案 |
| HTTP(S) 图片 | `ureq` 2 | 轻量同步 HTTP 客户端（加载 URL 图片） |
| CLI | `clap` 4.x | 功能完善的命令行参数解析（仅 CLI crate） |

```
│   └── elements/             # 元素类型

│   ├── notes.rs              # notesMaster / notesSlide XML 生成
│   ├── animation.rs          # 动画/过渡 timing XML（24 种动画映射）
│   ├── theme.rs              # theme1.xml 生成
│   ├── slide_master.rs       # slideMaster / slideLayout XML
│   ├── content_types.rs      # [Content_Types].xml
│   ├── rels.rs               # 所有 .rels 文件 + 图片/超链接收集（含 notes 关系）
│   └── components.rs         # 高级组件展开为原始形状 Group
├── parse/                    # PPTX → JSON 解析管线
│   ├── mod.rs                # parse() / unpack() / extract_media() / notesIdLst 关联

│   ├── pic.rs                # 图片元素解析
│   ├── table.rs              # 表格元素解析（合并单元格、列宽）
│   ├── grp_sp.rs             # 分组元素解析（递归）
│   ├── background.rs         # 幻灯片背景解析
│   ├── animation.rs          # 动画 timing 解析（presetID 反向映射）
│   └── theme.rs              # 主题 XML 解析
└── utils/
    ├── mod.rs                # load_image_bytes（本地/URL）、detect_image_extension（扩展名+魔数）
    ├── constants.rs          # 单位换算、动画预设共享表、86 种形状映射（含反向）、虚线/端点映射、过渡、飞入方向
    └── xml.rs                # XML 辅助：颜色（含 alpha）、三字体（latin/ea/cs）、xfrm、fill、line、shadow
```

`web-server/` 为独立 crate（`json2pptx-web-server`，axum）：提供上传 PPTX → unpack 产物 → 前端编辑 → 写回产物 → repack 下载的 HTTP API（`POST /api/upload`、`GET /api/overview`、`GET /api/media/*`、`PUT /api/slide/:idx`、`POST /api/repack`），单会话模式，并直接服务 `web/dist` 静态文件。

`web/` 为前端工程（Vue3 + Vite + pnpm + TS + Pinia）：渲染引擎采用"固定逻辑画布（英寸×96px）+ `transform: scale` 缩放"的 DOM/SVG 方案（参考 PPTist 思路）；86 种 OOXML 形状在 `web/src/configs/shapes.ts` 中映射为 SVG path（程序化生成多边形/星形 + 手写常用 + 矩形占位兜底）；图表组件用 ECharts SVGRenderer 渲染；编辑交互（选中/拖拽/8 手柄缩放/旋转）基于 document 级鼠标监听 + store 即时提交 + 防抖快照撤销。

`cli/` 为独立 crate（`json2pptx`），模块化组织：

```
cli/src/
├── main.rs                   # 10 个子命令入口（unpack/repack/view/edit/render/query/validate/dump/schema/templates）
├── config.rs                 # 工作空间配置（~/.json2pptx/config.json）
├── path.rs                   # 树形元素路径解析（/slide[1]/group[1]/text[2]）
├── workspace.rs              # 工作空间管理（自动 unpack + mtime 复用）
├── view.rs                   # 第一层视图（text / layout）
└── edit.rs                   # 第二层修改（get / set / add / remove）
```

`tests/` 为集成测试目录：`roundtrip.rs`（回环）、`unpack_repack.rs`（解包/重建）、`cli_view_edit.rs`（CLI 两层操作）。

## 4. 生成管线详解

`generate()`（`src/generate/mod.rs`）的完整流程：

1. **克隆模型并应用模板**：读取 `model.template`，通过 `TemplatePreset::from_name` 查找预设；将预设的 12 色配色与字体 `merge()` 进主题；为未设置背景的幻灯片应用模板默认背景；
2. **校验**：至少包含 1 张幻灯片，否则报错；
3. **收集图片**：遍历所有幻灯片，用 `rels::collect_image_sources` 收集元素图片与背景图片的全部来源（本地路径 / URL）；
4. **加载图片字节**：`utils::load_image_bytes` 处理本地文件与 HTTP(S) URL；`detect_image_extension` 用扩展名 + 魔数（文件头）双重判断格式；
5. **生成 XML 部件**：依次调用各 `generate_*()` 函数生成 XML 字符串；
6. **ZIP 打包**：用 `zip::ZipWriter` 按标准顺序写入 `[Content_Types].xml` → `docProps/*` → `presentation.xml` → 主题/母版/版式 → 逐张 slide → `media/*`。

每个 XML 部件与生成函数的一一对应关系见 [OOXML映射参考](OOXML映射参考.md) 附录。

### 4.1 动画引擎（generate/animation.rs）

- 按 `trigger` 分组：`onClick` 新起一组，`withPrevious` / `afterPrevious` 归入当前组；
- 每种动画类型映射到指定 OOXML 行为节点（`animEffect`、`animMotion`、`animScale`、`animRot`、`animClr`、`set`）；
- **关键不变性**：所有属性动画节点必须携带 `<p:attrNameLst>`，否则 PowerPoint 会忽略动画。

### 4.2 高级组件展开（generate/components.rs）

10 种高级组件（progressBar / progressRing / barChart / lineChart / pieChart / ringChart / kpiCard / ratingStars / timeline / processFlow）在生成时展开为原始元素组合（`<p:grpSp>`），展开后组件类型信息不保留——回环解析后变成普通 Group。

- 柱状图/折线图/饼图/环形图为**形状模拟**（矩形 / cxnSp 折线 / pie 扇区 / blockArc 环段），非 Excel 图表对象；
- 折线图展开包含 `<p:cxnSp>` 连接线；饼图扇区用 `prst="pie"` + adj + 旋转实现；环形图用 `blockArc` 扇区（>180° 自动拆段）。

## 5. 解析管线详解

`parse()`（`src/parse/mod.rs`）的完整流程：

1. **解压 ZIP**：用 `zip::ZipArchive` 读取 PPTX；
2. **解析元信息**：尺寸（`<p:sldSz>`）、元数据（core.xml）、主题（theme1.xml）；
3. **解析幻灯片**：按 `presentation.xml` 的 `<p:sldIdLst>` 顺序逐张解析 `slideN.xml`；
4. **重建模型**：流式解析元素，还原为 Rust 模型，可序列化为 JSON。

### 5.1 解析策略（parse/slide.rs）

- quick-xml `Reader` 流式解析，**宽容模式**（容忍未知/缺失节点）；
- 通过 `cNvPr@id` 重建元素顺序；
- 动画通过 `presetID` + `presetClass` 反向映射为 JSON 动画类型；
- `<a:br/>` 合并回 `\n`，保证换行回环一致；
- 布尔 run 属性（b/i/u）与 `cap="flat"` 线端等细节均正确还原。

### 5.2 媒体提取（extract_media）

`extract_media()` 把 `ppt/media/*` 解压到指定目录（保留 `media/` 相对结构），并自动修正模型中 `ImageElement.src` 与背景图片路径为本地绝对路径。

### 5.3 解包与重建（unpack / repack）

`unpack()` 把 PPTX 解包为**按幻灯片拆分的 JSON 中间产物**（包镜像结构）：

```
out/
├── presentation.json       # 顶层结构，slides 为文件路径数组
└── ppt/
    ├── slides/slideN.json  # 每张幻灯片一个 JSON（标准 Slide 结构）
    └── media/imageN.*      # 媒体文件实体（保留包内路径）
```

- 图片 `src` 统一改写为 `ppt/media/imageN.ext`（相对产物根；URL 原样保留）
- `repack()` 是逆操作：读 `presentation.json` + 各 `slideN.json` 组装模型，将 `src` 重写为相对产物目录的绝对路径后调用 `generate`
- 典型工作流：`unpack` → 编辑各幻灯片 JSON（或替换媒体文件）→ `repack` 重建

### 5.4 背景图解析

`a:blipFill` 背景图解析还原为 `{"type":"image","src":"..."}` 格式的 background 对象。

## 6. ID 系统

| ID | 赋值时机 | 用途 |
|----|---------|------|
| `spId` | `generateSlide` 内自增，从 2 开始 | 形状 ID（`<p:cNvPr id>`），动画的目标引用 |
| `rId` | `generateSlideRels` 分配 | 图片 / 超链接关系 ID（slideN.xml.rels） |
| `internalId` | `generate` 顶层分配 | 格式 `el_<slide>_<index>`，内部标识 |

## 7. 关键技术点

### 字体处理（东亚字体）

`font_family` 同时输出三个字体槽：`<a:latin>`（拉丁）、`<a:ea>`（东亚，CJK 文本必需）、`<a:cs>`（复杂文字）。内置模板的次要字体均为中文字体（Microsoft YaHei、Noto Sans SC、SimHei、STKaiti、STSong 等），保证中文正确渲染。

### 透明度

`fill_alpha` / `line_alpha`（0.0–1.0）在颜色节点下输出 `<a:alpha val="N"/>`（× 100000 转十万分比）；`shadow.opacity`（0.0–1.0）输出千分比。

### 单位换算

所有换算集中在 `utils/constants.rs`（`EMU_PER_INCH = 914400` 等），完整换算表见 [OOXML映射参考](OOXML映射参考.md) 第 13 节。

## 8. 测试体系

### 测试组织

- **框架**：标准 Rust 集成测试（`tests/` 目录 + `#[test]`），无第三方测试框架；
- **数量**：**39 个集成测试**，分布如下：
  - `tests/roundtrip.rs`：30 个回环测试（生成 → 解析 → 断言等价，含 line / 表格合并 / 超链接 / notes / 86 形状遍历 / 图表展开）
  - `tests/unpack_repack.rs`：4 个解包/重建测试（含媒体字节一致性的完整回环）
  - `tests/cli_view_edit.rs`：5 个 CLI 集成测试（config / view / edit / 新元素端到端 / 错误路径）
- **辅助工具**（`tests/common/mod.rs`）：
  - `temp_pptx_path()` — 临时文件路径；
  - `create_dummy_image()` — 生成最小合法 1×1 红色 PNG；
  - `assert_positions_eq!` — 位置断言宏（容差 0.01 英寸）。

### 覆盖范围

- 空 slide、多 slide、自定义尺寸；
- 文本（简单文本、多段落 + runs、CJK 中文、特殊字符转义、换行、零尺寸位置）；
- 形状（椭圆、矩形、渐变填充、无填充、旋转、adjust 值）；
- 图片（裁剪、超链接、边框）；
- 表格（表头、单元格级样式、对齐）；
- 分组（嵌套文本和形状）；
- 背景（纯色、渐变、图片）；
- 过渡（8 种类型全部测试、速度、自动翻页）；
- 主题和元数据（颜色、字体）；
- 24 种动画回环；
- 单 slide 全部元素类型混合；
- JSON → PPTX → JSON 全流程等价；
- unpack → repack 中间产物回环（按幻灯片拆分、媒体字节一致）；
- view text/layout 输出、edit 全链路（get/set/add/remove）与路径错误处理。

### 运行测试

```bash
cargo test          # 运行全部测试
cargo test --test roundtrip    # 仅运行回环测试
```

## 9. 开发指南

### 环境

- Rust 1.75+；
- 构建：`cargo build`；运行 CLI：`cargo run --bin json2pptx -- <命令>`。

### 新增一种元素类型的步骤

1. **模型**（`src/model/elements/`）：定义结构体，加入 `Element` 枚举（serde `tag = "type"`）；
2. **生成**（`src/generate/slide.rs`）：实现该元素的 XML 输出；
3. **解析**（`src/parse/slide.rs`）：实现该元素的反向解析（保证回环）；
4. **测试**：在 `tests/roundtrip.rs` 添加回环用例；
5. **文档**：同步更新 [元素与组件参考](元素与组件参考.md) 与 [OOXML映射参考](OOXML映射参考.md)。

### 新增高级组件

1. 在 `src/model/elements/mod.rs` 定义组件结构体（如 `ProgressBar`），并加入 `Element` 枚举（`#[serde(rename = "type名")]`）；
2. 在 `src/generate/components.rs` 的 `expand_component` 分发中添加分支，实现展开逻辑（组件 → 基础形状 Group）；
3. 添加回环测试（注意：展开后解析为 Group，需按 Group 断言）。

### 新增模板预设

在 `src/model/template.rs` 用 `preset!` 宏添加静态常量（name / display / desc / bg / major_font / minor_font / 12 色），并加入 `ALL` 数组。模板会自动出现在 `templates` 命令输出中。

### 新增动画类型

1. 在 `src/model/elements/animation.rs` 的文档注释中补充类型名；
2. 在 `src/generate/animation.rs` 实现 OOXML 行为节点映射；
3. 在 `src/parse/animation.rs` 实现 presetID 反向映射；
4. 添加回环测试。

## 10. 已知限制

| 限制 | 说明 |
|------|------|
| 图表 | `bar_chart` 是形状模拟，不是真正的 Excel 图表对象 |
| 母版/版式 | 固定单一母版 + 单一版式，不支持自定义占位符 |
| 高级组件 | 生成时展开为 Group，回环解析后不保留组件类型 |
