# ai-pdf 往返评测报告（2026-10）

对 `ai-pdf` 的 `unpack`（PDF → JSON 包）与 `repack`（JSON 包 → PDF）做端到端往返评测：
在 1463 份真实 PDF 上批量跑通，再分层抽样 100 份做渲染像素对比，定位实现缺陷。

## 1. 评测方法

| 项 | 说明 |
| --- | --- |
| 语料 | 1463 份 PDF，取自 GitHub 公开测试集：pdf.js 983、pdfbox 162、pdfplumber 84、pypdf 70、pikepdf 60、pdfminer 56、ocrmypdf 41、pdf20examples 7 |
| 语料特点 | 含大量刻意构造的边界样本：损坏文件、加密、模糊测试产物、字体/图像/透明度/竖排/表单专项 |
| 往返流程 | `ai-pdf unpack <pdf> -o art/` → `ai-pdf repack art/ -o rebuilt.pdf` |
| 渲染 | pymupdf 1.28.2，100 DPI，逐页灰度图，差异分 = 平均绝对像素差 / 255 × 100（0 表示逐像素一致） |
| 抽样 | 按来源分层随机（seed=42），取 100 份往返成功样例，对比每份前 3 页 |
| 判定 | 差异 ≤1.0 视为视觉一致；>20 视为结构性错误 |

脚本：`run_eval.py`（批量往返）、`sample_compare.py`（抽样渲染对比）、`feature_scan.py`（特性关联分析）；已归档在 `docs/eval-2026-10/scripts/`，原始产物在 `/tmp/pdf-eval/`。

## 4. 缺陷清单

### P0 — 造成整页级错误的缺陷

#### 4.1 裁剪路径被当作填充矩形（`re W n` → 全页黑块）

- **现象**：原页白底或图文正常，重建后整页黑色。样例 `docs/eval-2026-10/sample-014.jpg`（annotation-line-without-appearance）、`sample-088.jpg`（issue-987-test）、`sample-033.jpg`（transparency_group）、`sample-034.jpg`（S2）。
- **证据**：`annotation-line-without-appearance.pdf` 内容流仅 `0.1 w q 0 0.028 611.971 791.971 re W* n ...`（纯裁剪，不绘制），提取结果却含 `{"type":"rect","w":611.97,"h":791.97,"fill":"#000000"}`，覆盖整页。
- **根因**：`src/unpack.rs:327-355` 的 `re` 处理在遇到 `re` 时立即产出 Rect 元素，不区分该矩形随后是被 `W/W* n` 用作裁剪，还是被 `f/S` 绘制。裁剪矩形按当前（默认黑）颜色落成实心矩形。
- **影响面**：16.2% 语料、15% 抽样（均差异 56.6，是最大视觉杀手）。

#### 4.2 CID 字体 W 数组未换算 1/1000 em（文本宽度放大 2 倍）

- **现象**：重建页文字被拉开（`H e l l o`）、行超宽被页面裁掉。样例 `sample-029.jpg`（issue15053）、`sample-002.jpg`（bug1529502）。
- **证据**：重建 PDF 中 `/DW 1000`，但 `/W [ 3 [569] 40 [1366] 43 [1479] 75 [1139] ... ]`。所用 Arial Unicode 的 `units_per_em = 2048`：空格 569/2048 = 0.278 em（正确），按 1/1000 解释则成 0.569 em。同一页文本块宽度：原文 278pt → 重建 504pt（1.81 倍）。
- **根因**：`src/repack.rs:313` 取 `font.glyph_width(gid)`（字体原始单位，见 `src/fonts.rs:45`），在 `src/repack.rs:344-349` 直接写入 W 数组；`FontDescriptor` 的 Ascent/Descent/BBox 同样使用原始单位。PDF 规范要求这些值以 1/1000 em 表示。
- **影响面**：所有走 CID 嵌入路径的重建（非标准字体或非 ASCII 文本即触发，抽样中 59%）。抽样文本宽度比中位 1.14、34% 超过 1.35。

#### 4.3 间接 `/Resources` 未解析，图片整页丢失

- **现象**：源 PDF 页面有图片，提取结果 0 个 image 元素且无警告。样例 `sample-031.jpg`（canvas.pdf 17 图 → 0）、`sample-011.jpg`、`sample-044.jpg`、`sample-057.jpg`。
- **证据**：`pikepdf/multipage.pdf` 6 页 6 图，仅提取 1 个（且是伪 JPEG）；`pdf.js/canvas.pdf` 第 1 页 17 个图 → 0。这些页的 `/Resources` 是间接引用（如 `/Resources 24 0 R`）。
- **根因**：`src/unpack.rs:184` 只取 `get_page_resources` 返回的**内联**字典（`Some(res)`），忽略其第二返回值 `resource_ids`（间接资源对象 id 列表）。lopdf 对间接 `/Resources` 返回 `(None, vec![id])`，代码走 `if let Ok((Some(res), _))` 分支直接跳过。
- **同类**：`Resources/XObject` 值本身为间接引用时（如 `canvas.pdf` 的 `/XObject 32 0 R`），`res.get(b"XObject").and_then(Object::as_dict)` 同样失败（`src/unpack.rs:185`），需先解引用。
- **影响面**：24% 页面使用间接 `/Resources`（抽样 200 份 279 页中 66 页），其中 19 页挂有 XObject；另有 1.2% 页面的 XObject 子字典是间接引用。

#### 4.4 图片整体留存率 9%

- **证据**：抽样 100 份前 2 页：原 87 图 → 提取 8（9%）→ 嵌入 1（1%）。
- **构成**：间接 Resources（4.3）＋ 不支持的滤镜（4.5）＋ JP2 不可嵌入（4.6）三者叠加。

### P1 — 造成局部错误或元素丢失的缺陷

#### 4.5 图像滤镜支持不完整

- **JBIG2Decode（16% 图像）与 CCITTFaxDecode（6%）**：直接跳过并告警（`src/unpack.rs:576-584` 解码失败返回 None）。样例 `sample-000.jpg`（cardinal.pdf 扫描件）、`sample-011.jpg`（Brotli 位图全丢）、`sample-039.jpg`（bug1992868 10 图 → 0）、`issue1985.pdf`。
- **Flate + DCT 双滤镜链**：`src/unpack.rs:564-569` 只要滤镜列表含 dct 就把**原始流**写成 .jpg；对 `/Filter [ /FlateDecode /DCTDecode ]`，`decompressed_content()` 在 DCT 层失败后回退原始内容，落盘的是 zlib 数据 → 11 份 repack 因 `not a valid JPEG` 失败（如 `pikepdf/multipage.pdf`、`pdf.js/bug946506.pdf`）。
- **Predictor 未反预测**：`src/images.rs:71-102` 直接按 `width×height×components` 截取解压数据；对 `/DecodeParms /Predictor 15` 的流（每行 1 字节滤波前缀），要么因长度不符静默丢弃（`multipage.pdf` 第 3 页报"不支持的色彩空间"，实为解码失败），要么把滤波字节当像素产出花图。

#### 4.6 JP2（JPEG2000）提取但不可嵌入

- **现象**：`.jp2` 被替换为 1×1 白色占位图（`src/repack.rs:147-149`），页面出现空白块。样例 `sample-002.jpg`、`sample-034.jpg`（S2.pdf 6 张图全丢）、`lichtenstein.pdf`。
- **证据**：重建 PDF 中图像对象为 `/Width 1 /Height 1`；15+ 份文件报 `image 'media/img-001.jp2' type .jp2 is not embeddable — replaced by placeholder`。
- **说明**：PDF 原生支持 `/Filter /JPXDecode` 直接透传 JP2 码流，无需转码；JPX 占图像 9%。

#### 4.7 `cs`/`sc`/`scn` 颜色算子未处理（ICCBased 等色彩全丢）

- **现象**：整页色块变黑。样例 `sample-090.jpg`（background-checks 表格全黑）、`sample-088.jpg`。
- **证据**：源内容流用 `/Cs1 cs 0.8 1 1 sc ... f*`，`Cs1 = [/ICCBased 13 0 R]`（N=3，等价 RGB）；提取结果 511 个 rect 填充色全部为 `#000000`。
- **根因**：`src/unpack.rs:304-319` 只识别 `rg/RG/g/G`，未实现 `cs/sc/scn`（含 ICCBased/CalRGB/DeviceN/Indexed）。ICCBased N=3/N=1 可直接按 RGB/灰度处理，收益大、改动小。
- **影响面**：6.7% 语料（InDesign/Illustrator/Ghostscript 输出常见）。

#### 4.8 Form XObject 不递归

- **现象**：表单内的文本、矢量、图像全部丢失。样例 `sample-033.jpg`（透明组）、`sample-034.jpg`。
- **根因**：`src/unpack.rs:390-397` 的 `Do` 只查图像 XObject 表，Form 一律忽略；未按 CTM 递归解释表单内容流。
- **影响面**：10.3% 语料、11.5% 页面（抽样 279 页中 32 页）。

#### 4.9 透明度与软掩膜不支持

- **现象**：半透明叠加变实心、渐变透明丢失。样例 `sample-048.jpg`（smask_alpha_bc）。
- **根因**：`gs`（ExtGState 的 `/ca`、`/CA`、`/SMask`、`/BM`）无处理；图像 `/SMask` 未合成；透明组（`/Group /Transparency`）未解释。
- **影响面**：12.4% 语料、13% 抽样（均差异 25.3）。

#### 4.10 渐变（shading）与平铺图案（tiling pattern）不支持

- **现象**：`sh` 着色与 `/Pattern cs /p1 scn` 填充的图形丢失或变黑。样例 `sample-066.jpg`（tiling-pattern-large-steps，原页为条纹图案，重建只剩一个黑矩形）。
- **影响面**：shading 2.7%、平铺图案 1.9% 语料。

## 5. 修复优先级建议

1. **裁剪路径**（4.1）：`re` 先挂起为候选路径，仅当后续 `f/S/B` 才落元素，`W/W* n` 丢弃或记为裁剪。改动集中在 `src/unpack.rs:327-389`。
2. **W 数组单位**（4.2）：`glyph_width` 输出统一换算 `×1000/units_per_em`（W、DW 缺省、FontDescriptor 各项一致）。单点改动，消除最大面积的文本布局偏差。
3. **间接 Resources / XObject**（4.3）：`src/unpack.rs:184-209` 同时遍历 `resource_ids` 并解引用，`XObject` 值先 `dereference` 再取 dict。
4. **图像滤镜**（4.5）：按滤镜链顺序逐层解码（flate → 反 Predictor → DCT 校验魔数）；JBIG2/CCITT 可先明确降级并保留警告，或引入解码库。
5. **JP2 透传**（4.6）：`.jp2` 直接以 `/Filter /JPXDecode` 嵌入，去掉占位符。
6. **颜色算子**（4.7）：实现 `cs/sc/scn` 对 ICCBased(N=1/3)/CalRGB/CalGray 的映射。
7. **Form XObject 递归**（4.8）：`Do` 命中 Form 时以当前 CTM 递归解释其内容流（需防循环引用）。
8. **健壮性**（4.13、4.15）：unpack 对 0 页报错；修正旋转判定为检查 b/c 非零。

## 6. 复现

脚本已随报告归档在 `docs/eval-2026-10/scripts/`，语料清单见 `corpus_manifest.txt`（来源/路径/大小）：

```bash
mkdir -p /tmp/pdf-eval && cd /tmp/pdf-eval
cp <repo>/docs/eval-2026-10/scripts/*.py .
# 按 corpus_manifest.txt 从 pdf.js / pdfbox / pdfplumber / pypdf / pikepdf / pdfminer / ocrmypdf 各仓库取样本到 corpus/
python3 run_eval.py                       # 批量往返 → results.jsonl
python3 sample_compare.py                 # 100 份抽样渲染对比 → diff_summary.json + samples/
python3 feature_scan.py samples           # 特性-差异关联
python3 feature_scan.py corpus            # 全语料特性分布
```

依赖：`pymupdf`、`pillow`、`numpy`（`pip3 install --break-system-packages`）；`ai-pdf` release 二进制。

产物：

- `summary_stats.json`：往返成功率与失败分类
- `diff_summary.json`：100 份抽样的逐页差异分
- `sample-*.jpg`：证据图（每份为 上=原页 下=重建页，最多各 2 页）
